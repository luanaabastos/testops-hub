# TestOps Hub v1.1.0

Status: **release notes prepared — tag and GitHub Release not published**

TestOps Hub v1.1.0 represents the completed public rename and product-clarity pass. It preserves the architecture and verified browser evidence published with the historical QualityOps Hub v1.0.0 release while aligning the public product and repository identity with TestOps Hub.

## Highlights

- Public product identity renamed from QualityOps Hub to TestOps Hub.
- GitHub repository renamed to [`luanaabastos/testops-hub`](https://github.com/luanaabastos/testops-hub).
- Product copy clarifies the problem, evidence boundaries, quality metrics, and regression workflow.
- Six refreshed public screenshots use the TestOps Hub identity.
- Real Cypress/Mochawesome and Playwright JSON evidence remains linked to its workflows, artifacts, and dashboard executions.
- README and portfolio materials distinguish Official CI, Hosted Preview, Demo Data, and Local Demo.

## Architecture

```text
GitHub Actions
→ Cypress / Playwright
→ retained report artifact
→ authenticated Fastify ingestion API on Render
→ versioned adapter
→ normalized execution
→ Neon PostgreSQL
→ React dashboard on Render
```

Real browser execution stays in GitHub Actions. Render hosts the React application and Fastify API, and Neon persists normalized execution history. Hosted Preview demonstrates the ingestion stages without starting a browser or creating official evidence.

## Limitations

- Every product and displayed data point is fictional and synthetic.
- PocketWallet is a deterministic Mobile Harness Demo, not a real mobile-device run.
- Render Free can cold-start and provides no availability commitment.
- There is no user identity model, multi-tenancy, distributed queue, or distributed rate limiting.
- GitHub Actions retains external-CI reports; independent object storage is not enabled.
- Hosted Preview starts no browser and creates no official execution.
- The hosted URL and stable internal package, environment, and database identifiers retain `qualityops-hub` naming to avoid an unrelated migration.
